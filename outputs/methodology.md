# 方法论说明：一个陌生品类，3 天从数据到新品

## 一、研究过程（实际走过的路）
| 步骤 | 做了什么 | 产出 | 用的工具 |
|---|---|---|---|
| 1. 选品类 | 按“数据可获取、工艺可讲、视觉可做、不撞示例、跟个人方向契合”打分，选定**猫用智能硬件**（欧美） | 品类决策 | Claude 讨论 |
| 2. 供给端摸底 | 8 个品牌官网的 Shopify 公开接口 `/products.json`，抓 427 条 → 规则清洗出 107 款主机单品 → 功能矩阵、价格分布 | `products.csv`、`feature_matrix.csv` | Python（不用 AI） |
| 3. 需求端找痛点 | 亚马逊 18 款热销品的 “Customers say” 话题（情绪 + 提及次数）；Reddit 5 帖；X 18 条 | `amazon_aspects.csv` 等 | opencli 只读访问 + Python |
| 4. 洞察与机会 | 交叉验证：供给有空白 × 需求有负面话题 × 有溢价信号 → 3 个机会点 | `insights_v1/v2.md` | Claude |
| 5. 挑刺 | 换一家模型（DeepSeek 推理模型）审稿 → 推翻 2 条结论、改了产品承诺 | `critic_deepseek.md` | DeepSeek API |
| 6. 新品方案 | 定位、定价、7 个卖点（每个标证据等级）、材料结构工艺、单位经济、风险 | `product_plan.md` | Claude |
| 7. 设计 | 统一“产品锚定描述” → 4 张一致的设计图；两家模型对比；程序化 3D 模型；网页海报 | `assets/`、`web/` | GPT Image、Seedream、three.js |
| 8. Demo | 把以上串成可交互网页，并做“换品类实时重跑” | `app.py`、`pipeline.py` | Streamlit、DeepSeek API |

## 二、AI 工具怎么用（以及为什么这么分工）
- **能用规则就不用 AI**：抓取、清洗、计数用 Python——透明、可复查、零成本。AI 只放在需要“理解”的环节。
- **固定流水线，而不是让 AI 自由聊天**：任务是一环扣一环的，拆给多个 agent 互相对话反而容易乱；角色之间只交文件，每一步都可追溯。
- **挑刺要换模型**：同一个模型审自己，容易错到一块去。Claude 写、DeepSeek 审，审出的问题必须在方案里回应。
- **按难度派模型**：判断最多的分析和方案给 Claude；网页里需要实时、要控制成本的部分用 DeepSeek（实测：1 次方案审查 + 2 次完整重跑，账户余额共减少 ¥0.12；按同一账户余额变化计算，期间如有其他调用会略有高估）。
- **出图先比再用**：同一段提示词对比 GPT Image 和 Seedream，按“提示词要求符合度”选主力；图里的文字不交给 AI 画，用网页排版。

## 三、怎么复制到其他消费品类
只需要换两样输入，其余不变：
1. **品牌官网列表**（Shopify 独立站，欧美 DTC 品牌大多是）；
2. **亚马逊搜索词**（拿需求端话题）。

在猫用智能硬件这一版里，“分类、打标签”是我手写的规则；Demo 的 ⑥ 把它换成了大模型打标签，所以换品类不用改代码——已用“咖啡器具”实测：3 个品牌 515 条 → 49 款主产品 → 新品概念，全程约 1 分钟。

**可复用的判断框架**：机会点 = 供给端功能空白 ∩ 需求端负面话题 ∩ 溢价信号；每个卖点标证据等级（量化 / 质性 / 估算 / 未验证），估算不得进入定价结论。

## 四、局限（如实）
- 用户原话样本小（Reddit 5 帖、X 18 条），只用于解释“为什么”，规模判断以亚马逊为准；
- 品牌清单只选了“官网能抓”的，美国头部 Litter-Robot 没进样本，存在选择偏差；
- 亚马逊 “Customers say” 本身是 AI 汇总，只用话题和次数；部分商品共用评论汇总，已去重；
- 成本、续航、精度都是估算，需要供应商报价和原型测试；
- 没有绕过任何网站的登录或人机验证：YouTube 视频页要求登录验证、亚马逊单条评论需要登录，这两处数据没有使用。
